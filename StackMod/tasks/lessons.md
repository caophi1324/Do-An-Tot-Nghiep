# Lessons Learned & Error Prevention Rules

## Patterns & Guidelines
1. **Model & Package Availability**: Always verify package imports (e.g. `uniface`, `ultralytics`, `faiss`) and model checkpoint downloading/caching before running full pipelines.
2. **Coordinate Space Consistency**: Ensure bounding boxes and facial landmarks extracted from person crops are properly mapped back to original frame coordinates before quality assessment and visualization.
3. **Bounding Box Smoothing**: Apply One Euro Filter on `(cx, cy, w, h)` representation instead of 4 corners to prevent shape distortion and jitter during face/person movement.
4. **Graceful Fallbacks**: If hardware acceleration (DirectML/CUDA) is unavailable, fallback smoothly to CPU ONNX Runtime without failing.
5. **Thread Safety**: Video capture sources, pipeline processing, and UI updates run in separate threads communicating via safe queues / Qt Signals. Never block the UI thread with model inference.
6. **Proactive Requirement Clarification on Open Decisions**: When a plan or specification document includes an explicit section of open questions or early decisions (e.g., Section 13: "Việc cần quyết định sớm"), MUST actively ask and align with the user using the `ask_question` interactive tool to tailor the deployment to their exact infrastructure and use-case needs.
7. **DirectML Engine Monitoring on AMD Windows**: DirectML on AMD RDNA 3 / DirectX 12 submits command lists to the Direct3D 12 3D queue (`engtype_3d`), not legacy `engtype_compute 0`. Always inform users to monitor the `3D` GPU engine or verify throughput benchmarks.
8. **Multi-Sample Active Learning & Cross-ID Distinctiveness**: When locking a target, collect a quota of 5 diverse high-quality angles (1 Anchor + 4 Adaptive Poses). Protect against cross-contamination using crowd overlap check (`IoU > 0.25`), 2-stage consecutive-frame confirmation (`pair_sim >= 0.80`), and cross-identity margin verification (`margin = sim_self - sim_other >= 0.15`).
9. **Qt Signal Backpressure, DirectML Concurrency, and Viewport Scaling**:
   - In high-throughput Qt/PySide6 video pipelines (30-60 FPS), queued signal-slot connections between background threads and the GUI thread will accumulate an unbounded queue if drawing takes longer than frame interval. Always implement a backpressure frame-drop guard (`threading.Event()` check).
   - In ONNX Runtime DirectML, never call `session.run()` concurrently across multiple threads without an explicit synchronization lock (`threading.RLock()`), as DirectX 12 command queue collisions will hang the GPU driver or freeze the application.
   - Never use software CPU scaling `QPixmap.scaled(..., Qt.SmoothTransformation)` on full 1080p frames in the GUI thread every frame (costs 15-25ms CPU rasterization); instead use direct viewport painting `painter.drawPixmap(target_rect, pixmap)` which delegates blitting to the GPU swapchain.
   - Never perform synchronous disk I/O (`faiss.write_index()`, DB commits) inside the real-time frame pipeline loop; always offload to dedicated background worker queues.
10. **Multi-hundred Frame Stress Testing**:
   - Short benchmarks (30-50 frames) only exercise the warm-up and initial acquisition phases. Conditional branches like crowd anti-overlap guard, active learning candidate proposal, and identity hysteresis only activate after dozens of frames. Always run at least 500-1,000 frames to verify long-term stability and uncover edge-case variable scope bugs.
11. **Streaming Generators & Token Typing in ASGI TestClient**:
   - Starlette / FastAPI `TestClient` executes synchronous streaming generators inside threadpools. An infinite `while True` generator will freeze `TestClient` indefinitely because `TestClient` waits for the app response lifecycle to complete. Always decouple generator logic into a modular chunk generator with a controllable `max_frames` bound (`STREAM_MAX_FRAMES: Optional[int] = None`).
   - In FastAPI endpoints using `from __future__ import annotations`, always import `Request` at module global scope so FastAPI's reflection resolves ASGI `Request` parameters rather than treating them as unresolvable models (causing HTTP 422).
   - When issuing purpose-specific JWT tokens (e.g., dedicated short-lived stream tokens), strictly assert `payload.get("type") == "access"` in `get_current_user` to prevent token substitution attacks across API boundaries.
12. **Face BBox Smoothing, Landmark Dynamic Propagation & Spatial Lock Continuity**:
    - **Dual-source & Detector Jitter**: Never pass un-smoothed detector boxes directly into visualization or state tracking. Always smooth face bounding boxes (`smooth_face_bbox`) via dedicated OneEuro filters on `(cx, cy, w, h)` to prevent high-frequency detector noise and 10-25px jumps between detection and extrapolation frames.
    - **Cadence Landmark Detachment**: When skipping face detection frames (cadence) to save CPU/GPU, never freeze 5-point facial landmarks at stale static coordinates (which detach from moving faces). Instead, propagate landmarks dynamically using head bounding box displacement and scale ratio (`propagate_landmarks_motion`).
    - **Receptive Field Crop Margins**: When detecting faces inside object/person crops, never slice tight against raw YOLO bounding box borders. Always add 10-15% contextual padding (top and sides) to provide surrounding context for CNN feature extractors, preventing truncated forehead/hair and missing chin/mouth landmarks.
    - **Spatial Lock Hand-off**: In multi-target tracking systems, ByteTrack can switch track IDs upon rapid movement, momentary detector drop, or brief occlusion. Never rely solely on a fragile integer `locked_track_id`; always maintain spatial continuity with `_last_locked_box` and automatically migrate lock to overlapping active tracks (`IoU >= 0.30`).
13. **OpenCV VideoCapture FFMPEG Parameter Constraints & Qt Font Unit Semantics**:
    - **OpenCV FFMPEG Open Parameters**: In OpenCV, passing `cv2.CAP_PROP_BUFFERSIZE` into `params` in `cv2.VideoCapture(uri, cv2.CAP_FFMPEG, params)` causes FFMPEG's `cap_ffmpeg_impl.hpp` to immediately bailout with `unsupported parameters in .open()`, preventing network/DroidCam streams from ever connecting. Only pass supported open properties (`CAP_PROP_OPEN_TIMEOUT_MSEC`, `CAP_PROP_READ_TIMEOUT_MSEC`) to `.open()`, and set `cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)` after the stream is opened.
    - **URI Normalization for Mobile Webcams (DroidCam)**: DroidCam phone apps stream MJPEG over HTTP on port 4747 at `/video` (or `/mjpegfeed`), while requesting root `/` returns an HTML web page. Always normalize IP/port entries (`http://<ip>:4747` -> `http://<ip>:4747/video`) to prevent OpenCV from trying to decode HTML as video frames.
    - **Qt Point Size vs Pixel Size Semantics**: Defining `font-size: <N>px;` on `QWidget` in QSS causes `QFont::pointSize()` to return `-1` (undefined in points). On Windows with High-DPI PassThrough scaling, native controls calling `font.setPointSize(font.pointSize())` trigger the warning `QFont::setPointSize: Point size <= 0 (-1), must be greater than 0`. Always configure a valid application default font (`app.setFont(QFont("Segoe UI", 10))`) and use typographical point sizes (`pt`) in stylesheets.
14. **Settings Persistence & Dock State Synchronization**:
    - Dock controls (such as sliders in `TuningDock`) must never hardcode arbitrary defaults in `__init__` that disregard or overwrite user configuration. Always expose `apply_config(cfg)` and initialize all sliders from the loaded `AppConfig`.
    - Ensure all runtime changes (tuning sliders, overlay flags, presets, settings dialog) continuously update the central configuration and persist atomically to disk (`data/config.json`) including on application exit (`closeEvent`).
15. **Viewport Margin Utilization & Live Tracking Avatar HUD**:
    - When displaying aspect-ratio-constrained video inside arbitrary viewport windows, the empty pillarbox margins (`dest_x > 0`) can be creatively utilized for live identity tags, target face avatars, and status meters without occluding the main camera feed.
    - Implement an adaptive floating fallback when pillarbox margins are too narrow (`dest_x < 110px`), ensuring critical target identity indicators remain visible regardless of window resizing or aspect ratio changes.
16. **Active Learning Freezing, Identity Splitting & Re-Identification Thresholds in Real Camera Feeds**:
    - **Click-to-Lock Identity Splitting**: Clicking to select/lock a target must never unconditionally enroll a new sequential person ID (`Person N+1`). Always perform an instant vector search against the enrolled database (`threshold=match_thr`). If the face matches an already-enrolled person, re-link to their existing identity. Creating multiple duplicate IDs for the same person fractures the database, dilutes voting consensus across duplicates, and leads to permanent classification as `Unknown`.
    - **Cosine Similarity Reality & Re-ID Thresholds**: For deep face embedding models (like EdgeFace-XXS), natural intra-person cosine similarity across different sessions, camera re-entries, and lighting ranges between 0.50 and 0.65. Setting `match_thr = 0.68` causes consistent re-identification failure. An optimal configuration is `match_thr = 0.50`, `hysteresis_thr = 0.42`, and `vote_min = 2`.
    - **Multi-Sample Staging Retention**: When collecting diverse adaptive templates, a frame that happens to be redundant with the existing database (`sim_self > max_self_sim`) must not aggressively purge `staging_emb = None`. Clearing the staging buffer on redundancy destroys candidate momentum and causes active learning to stall at 1/5. Furthermore, when `sim_self >= 0.80`, competing high matches in the DB indicate duplicate identities rather than genuine ambiguity, and should not block adaptation.
